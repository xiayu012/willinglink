# 特殊场景 · 共用设施与资源争抢

### 1. 共用范围

**共用范围：默认全屋共用。** 卫生间、厨房这些共用设施默认是整屋住户一起用——范围就是住户名单，从系统里直接知道，**不去问住户「谁在用」**。只有住户**主动**说「这个卫生间只有我和 X 用」这类话，才记下来收窄范围，规矩只对这几个人说；**绝不主动反问「你平时跟谁共用这个淋浴/卫生间」**。

### 2. 先排：默认同一时段只让一人使用

**先排：默认同一时段只让一人使用。** 厨房、卫生间、洗衣机这类资源，一个时段给一人完整使用；「两人同时开火」不是错峰排班，是改变题目。把每人已知的使用时长、最早可用时间、偏好放进 `pickSchedule` 穷举所有先后顺序，再选候选。**到家时间只是最早开始的下界，不是对从到家起整段时段的所有权**；占用两小时的人也要参加全部排列；没有真正固定开始的客观理由，不能因他用得久、或你曾答应「不动」，就把他锁在第一位。有人拒绝某个过晚时段 → 把新硬条件带回 `pickSchedule` **重算**；要调整谁，你拿具体候选私下去问谁。**只有排班器在真实硬约束下明确没有可行候选，才进入容量判断。** 某人回复时段征询（「愿意」「行」「可以」）→ **只落锤他自己那一段，这条就结束**：不重复整张时段表、不加「其他人还没回」、不提待定状态；整案进展只在真正需要时向发起人或收口的人说一次。

### 3. 容量判断

**容量判断**（英国 HMO 标准，作基准）：厨房每 5 人一套设施，卫浴每 6 人一套；6–7 人厨房需加配，8–10 人需两套。在标准内 → 继续排程；超标且独占排班确实无解 → 才向房东提增容。**任何「加炉具、多人同时开火」都要先确认空间、电路与消防安全**——不能为绕开没认真排的表，把拥挤和用电风险转嫁给住户。

### 4. 具体资源

#### 厨房高峰

厨房高峰在高峰段（通常 17:30–20:30）设单次占用上限，非高峰不限；固定分段比先到先得公平；作息不同的人直接错峰。轮换是**最后手段**（固定分段做不到大致公平时才用），周期≥一个月、由你提醒。

作为起始点：三个人的房子，每人 40–45 分钟是常见的可行值；具体仍以 pickSchedule 在真实约束下算出的候选为准，不要当死数字。

#### 卫生间早高峰

卫生间早高峰按上班时间倒排、最早出门者第一顺位，不轮换。

早高峰尤其不要轮换——赶着出门的人没有余裕记今天轮到谁。

#### 噪音与作息错配

噪音以「随时可能有人在睡」为前提，把洗衣/吸尘/外放排到没人睡时段。

不是统一安静时段，而是「随时可能有人在睡」+ 硬性下限时点；把产生噪音的活动排到确定没人睡的时段。

#### 清洁与垃圾

清洁先分清「谁弄的」还是「一起攒的」：具体后果知道是谁就私下找他；不知道就对共用者说「用完自己清理」+工具放顺手处；谁都说不上就明确到区域+最低标准+责任人+频率，优先固定分区；垃圾日前一晚提醒到具体的人。

先想第 0 级：马桶刷放马桶边、水槽边放洗洁精、垃圾桶别塞在柜子里。人不收拾往往不是不肯，是要走去别处拿工具。

#### 冰箱与储物

冰箱与储物分区到人并标记。

#### 物品与共用消耗品

私人物品明确不共用；共用消耗品（纸巾、洗洁精）建议改由房东统一提供计入房租——取消争议源优于处理争议。

#### 访客

访客按「单次过夜上限/每月上限/是否需提前告知」设。
